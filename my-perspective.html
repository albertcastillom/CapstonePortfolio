Personal reflection

My Perspective

Where I started

I started this project with the vision of a screen time app that took an existing habit of mine and made it into an app that everyone can use. This idea came to me because I often study with a friend as a way to hold me accountable. Instead of being on a call with a friend this app would allow me to send them a focus session request. They could then see what my task/goals were and make sure I completed them. At the beginning of this project I knew React and wanted to transfer those skills to mobile development with React Native. After doing research on how to implement the project, I realized I would have to do it in Swift and SwiftUI. If I wanted the best performance and user experience this was the way to go. I was uncertain if I could bring this app to my envisioned 100% in the 300 hours alloted for the capstone, while having to learn a new language. My early goals were to learn the language and create a UI worthy of an amazing application and being able to implement the main feature. I hit these goals and then I needed to polish the app and add other basic Screen time features to make it a fully usable and desirable app.

What challenged me

When I started the project I did research and planning to a level I thought was sufficient. It turns out my research and planning was not enough to prepare me for the challenges I would face. I should have planned the entirety of the project but I was too eager to start building and I wanted to see my ideas come to life. I jumped right into building the UI after making some mockups and a rough plan of the app, this was in React Native. After a few days of building I realized that React Native was not the best option for this project and I would have to switch to SwiftUI. This was a big challenge because I had to learn a new language and framework while also trying to implement the app. I had to learn how to use SwiftUI and understand the differences between it and React Native. I also had to learn how to use Swift and understand the differences between it and JavaScript.

I felt like I was breezing through the UI even though using SwiftUI was new. After a few weeks, the complexity of the project kept increasing and the Swift classes and different stlye of programming (Apples declartive vs imperative programming) was becoming apparent. Breezing through became long hours of reading documentation and debugging or just trying to figure out how to do certain things. The project was quickly becoming harder and harder to navigate and follow. I had to learn a new language at a high level to implement the screen time feature and even be able to activate the permissions for it. To help with this I seperated my code files into features instead of models, views, and view models. This helped me narrow down the code I was working on and make it easier to debug. This experience taught me that its okay to slow down, plan and really work things out.

Strategies that worked

A few strategies helped me make progress, things like focusing on a few things a time, planning your next steps, taking a look at similar code and learning anything you dont understand. By planning my next steps I was able to sit down with a small goal in mind and complete it, overtime those goals added up and the project was looking more complete. When I was really stuck or didn't know the proper way to implement a class or something, I looked up videos, looked back through tutorials and even looked at some prototypes. Once I new how it was being implemented I would research any syntax I didn't understand and figure out why it was used there. These strategies kept the project moving even if slowly, but any progress is better than no progress.

What I would do differently

I would have spent more time planning and researching before starting to build. This would have helped me understand the project better and make better decisions. I would have also spent more time learning Swift and SwiftUI before starting to build. This would have helped me understand the language and framework better and make better decisions.

During the implementation, I would have refactored my code base while building. This would have kept the codebase more manageable, while limiting the amount of copy and pasted code. The beginning would have benefited from view components and private functions that help clean up and reuse the written code. I would also have created a project theme pack, consisting of the apps color theme, common sizing, border radius's, components, etc. A theme pack like this would create a better looking and functioning prototype that is cohesive. Lastly, I would have followed the KanBan method more strictly. I would have used a KanBan board like Trello to keep track of my progress and make sure I was staying on track. This would have helped me stay organized and focused on the most important tasks, but most importantly keep me informed on exactly what came next.

Conclusion

Quarter one of the capstone was a learning experience, I learned a lot about myself and my abilities. I learned that I can learn quickly and adapt to changes. I also learned that I can meet my goals and complete a project, even when faced with challenges. I learned that I can build and deploy real projects, and that I can create a full UI experience that functions as intended. It also taught me that I shoudl plan more and research more before starting to build, and that I should refactor my code base while building. These lessons will help me in my future career as a developer, and I will take them with me as I continue to grow and learn. They also serve as great talking point with future employers and show that I can learn quickly, adapt to changes, and meet my goals.
