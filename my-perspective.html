Personal reflection

My Perspective

Where I started

I started this project with the vision of a screen time app that took an existing habit of mine and made it into an app that everyone can use. This idea came to me because I often study with a friend as a way to hold me accountable. Instead of being on a call with a friend this app would allow me to send them a focus session request. They could then see what my task/goals were and make sure I completed them. At the beginning of this project I knew React and wanted to transfer those skills to mobile development with React Native. After doing research on how to implement the project, I realized I would have to do it in Swift and SwiftUI. If I wanted the best performance and User experience this was the way to go. I was uncertain if I could bring this app to my envisioned 100% in the 300 hours alloted for the capstone, while having to learn a new language. My early goals were to learn the language and create a UI worthy of an amazing application and being able to implement the main feature. I hit these goals and then I needed to polish the app and add other basic Screen time features to make it a fully usable and desirable app.

What challenged me

When I started the project I felt like i was breezing through the UI even though using SwiftUI was new. After a few weeks, the complexity of the project kept increasing and the Swift classes and different stlye of programming (Apples declartive vs imperative programming) was becoming apparent. Breezing through became long hours of reading documentation and debugging or just trying to figure out how to do certain things. The project was quickly becoming harder and harder to navigate and follow. I had to learn a new language at a high level to implement the screen time feature and even be able to activate the permissions for it. To help with this I seperated my code files into features instead of models, views, and viewmodels. This helped me narrow down the code I was working on and make it easier to debug. This experience taught me that its okay to slow down, plan and really work things out.

Strategies that worked

A few strategies helped me make progress, things like focusing on a few things a time, planning your next steps, taking a look at similar code and learning anything you dont understand. By planning my next steps I was able to sit down with a small goal in mind and complete it, overtime those goals added up and the project was looking for complete. When I was really stuck or didn't know the proper way to implement a class or something, I looked up videos, looked back through tutorials and even looked at some prototypes. Once I new how it was being implemented I would research any syntax I didn't understand and figure out why it was used there. These strategies kept the project moving even if slowly.

What I would do differently

Currently, I would have refactored my code base as I was building. This would have kept the codebase more manageable, while limiting the ammount of copy and pasted code. The beginning would have benefited from view components and private functions that help clean up and reuse the written code. I would also have created a project theme pack, consisting of the apps color theme, common sizing, border radius's, components, etc. A theme pack like this would create a better looking and functioning prototype that is cohesive.

What comes next

This project relates to my future career because it shows I can build and deploy real projects. I implemented a full UI experience that functions as intended and a working backend, that ensures user privacy and secutity. Trough the develoment of this project, it also show I can learn quickly, adapt to changes, and meet my goals.
